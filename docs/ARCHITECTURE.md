# Architecture

The game ships as one self-contained `index.html`, built from the modules in `src/` by `node build.mjs`. There is no bundler and no runtime dependency beyond three.js (pinned in `src/manifest.json`, loaded from jsDelivr as an ES module that sets the global `THREE` before the game module runs; see `threeTags` in build.mjs), and PeerJS when you play online. The simulation does its vector math with the game's own `Vec3` (`core/vec3.js`), so a three.js upgrade cannot change how a match plays. `node build.mjs --trailer` builds the trailer recording page (`out/trailer.html`): the game plus `manifest.trailer` (its modes, and engine modules only it needs). `node tools/sizes.mjs` lists each module's minified size.

## Layout

```
src/
  manifest.json        load order (the single source of truth)
  html/                page template and HUD partials
  styles/              base, CTF and multiplayer-panel CSS
  core/                prelude helpers, settings, input, gamepad, audio, announcer
  render/              renderer, post-processing pipeline, environment and materials, pooled FX
  world/               physics and collision, destruction, maps and their sci-fi dressing
  characters/          pilot rig: motion-captured locomotion (anim.js) under procedural layers (rig.js)
  player/              aim assist, ground-pound marker
  weapons/             arsenal data, firing, weapon models, viewmodels and their animation, grenades, rockets, pickups and floor items
  ui/                  HUD, reticle, settings screen
  game/                game state, deploy, main loop, drop pods, the sandbox (tuning settings), the window.KA API
  modes/               trailer and its synthesized score (trailer build only); ctf/ (map, nav, AI brain and agents, rules, UI, play and simulation modes)
  net/                 arena presence sync, CTF host and client, peer-to-peer room transport
tests/                 headless sim, browser and render tests
types/                 TypeScript declarations: globals, the KA API type, wire formats, settings schema
tools/                 build helpers (module scope analysis, unused-name check), trailer recorder, sandbox tuning simulations (tune.js)
docs/MODULES.md        generated index of what each module declares
docs/EXECUTION.md      what runs, in what order: build, page load, every frame, matches, online, headless
docs/EXTENDING.md      recipes for adding a HUD widget, setting, weapon, map, mode, AI behaviour or animation
```

## How modules connect

- **Engine modules** (`manifest.engine`) are concatenated, in order, into one strict-mode closure. They share a scope, so a module can use anything declared by modules listed before it, and functions declared anywhere (calls resolve at run time). Keep cross-module use to what `docs/MODULES.md` lists.
- **Mode modules** (`manifest.modes`) are each their own closure. They only talk to the engine through `window.KA` (exported by `game/exports.js`) and to each other through `window.CTF`. This is the boundary to preserve: new modes should use `KA`, not engine internals.
- **The multiplayer transport** (`net/p2p-transport.js`) provides `window.KAHOST.use("room")`, a presence-room interface: `presence(patch)`, `peers()`, `onPeers(cb, onClose)`, `join(name)`. Any transport implementing it (a relay server, a native socket layer) can replace it without touching the netcode.
- **Pilots** (`game/pilot.js`): every player-shaped thing (you, drones, online players, CTF agents, trailer actors) is a `Pilot` with a stable id, a `Body`, an optional rig and a controller kind (`local`, `ai`, `net`, `script`). Registered pilots live in `PILOTS` by id (`local`, `bot:<n>`, `peer:<id>`, `actor:<n>`); CTF agents use the same fields and their own ids because the match owns them. Anything that only needs a body and a rig (posing via `posePilot`, kill cams, recordings, stats) is written once against this shape.
- **Events** (`game/events.js`): one stream for kills, damage, medals, sprees, pickups, spawns, flag events and match start/end. Each event carries stable pilot ids, display names, the weapon and the current map and mode (`EVENTS.setContext`). The kill feed and medals are subscribers; CTF forwards its rule events into the same stream. Stats, highlights and challenges should be added as subscribers (`EVENTS.on(type or "*", fn)`), not as hooks in gameplay code. `EVENTS.recent(n)` returns the rolling log.
- **Recording and determinism** (`game/recorder.js`, `core/rng.js`): the recorder keeps the last 45 s of every pilot's position and full rig pose state at 30 Hz (`REC.sample(id, t)` interpolates; ids match the event stream), and an effects track in a preallocated ring: every tracer, explosion and shockwave as it is drawn (hooked in `render/fx.js`, so every shooter is covered: you, drones, CTF agents, online players) and where each grenade, rocket and drop pod in flight was. Simulation randomness (AI, rules, spawns) goes through the seeded `rand()`; a CTF match started with the same `seed` replays identically (checked in `tests/sim.test.js`). Visual-only randomness stays on `Math.random`.
- **Cinema** (`render/cinema.js`): shared camera toolkit. Shots are functions of time returning `{ p, l, fov }`: `orbit`, `track` (chase / over the shoulder, pulled in front of walls), `firstPerson` (a recorded pose's eyes, for replays), `crane` (blend two shots), `fixed`. `CINE.apply` places the camera with smoothing, shake and roll; `letterbox`, `card`, `caption`, `flash` and `slowmo` (game-time scale) drive the shared overlay, and `look({ dof, focus, range, grade, ca, streak })` switches the post pipeline to a cinematic look (depth of field from the depth buffer, split-tone grade, lens fringing, anamorphic streaks; `look(null)` restores the game look). The spectator director, the match intro, kill cams and Play of the Game use the camera toolkit and overlay; only the trailer uses `look`, so its shaders and passes (`render/cine-look.js`) ship in the trailer build only.
- **Replays** (`game/replay.js`, `game/highlights.js`): `REPLAY.play` shows a window of the recording (live, or a saved clip) through ghost rigs while the live pilots and projectiles are hidden and the world keeps simulating; it draws the recorded tracers, explosions and projectiles again, knocks ghosts down and flashes their shields from the event log, and in first person poses the viewmodel from the subject's recorded state (weapon, aim and scope zoom, sprint, reload, melee; their shots flash and kick). The kill cam replays the last seconds before your death through the killer's eyes (up to 4.5 s, as long as the respawn allows; `KILLCAM_T`), slows down on the killing blow and names the killer and weapon; a death with no killer to look through (a fall, your own grenade, a pod) orbits where you went down. It ends before you respawn. With drop pods your pod waits for it (`killCamHolds`) and launches when it ends or is skipped; it is cut to fit before the pod would launch, and when the respawn is too quick for its shortest slow-motion cut the pod waits that long (free for all: back in control 6.45 s after dying instead of 6.35 s; capture the flag: unchanged at 7.35 s). Highlights score kills (multikills, sprees, power moves), captures and returns from the event stream and save clips of the best three; at match end the best one plays as Play of the Game (title card, first person with slow motion on the kills, then an orbit). Each client picks from what it saw, so online players see the same moment in almost every match.
- **Game modes** (`game/modes.js`, `data/modes.js`): a mode registers with `defineMode({ id, name, settings, start })` and, while running, hands the engine a hooks object via `extPlay` (`tick`, `targets`, `respawn`, `onPlayerDeath`, `onFx`, `pickups`, `scores`, `switchTeam`, `carrying`, `carryNoRun`, `dropFlag`, `exit`; all optional). The four match modes are `PLAY_MODES` in `data/modes.js` (name, one line, key points, maps, what the score counts): **Capture the Flag** (Twin Foundry), **Team Slayer**, **Free-for-all Slayer** and **Team Oddball** (the arena or Twin Foundry). All four play on `CTF.Game` with its `rules` (`modes/ctf/rules.js`) and register from `modes/ctf/modes.js`, offline, hosting or joining; `spectate` is AI vs AI in any of them. Their score and time limits (and oddball's time to win and skull reset) are settings in **Settings → Modes**, read through `modeRules(id)`; online, the host's apply. The engine's own `practice` mode is the practice arena (drop in with drones and online players, no host). Every mode number lives in `data/modes.js`.
- **The menu** (`ui/menu.js`): the match modes as cards in a radio group (name, line, key points, limits); the picked mode's map, team, team size or pilots and bot skill; a Rules button that opens Settings → Modes on that mode; a summary of exactly what Play starts and a Play button that names it ("Play", "Host" in a room, "Join" when the room already has a match, whose mode then takes over the picker). The pick is saved (the `menu` document). The match modes supply the room's lobby through `MENU.lobby`.
- **Carrying** (the flag in capture the flag, the skull in oddball): both hands are on it, so no guns or grenades, and a melee with it kills in one hit (the kill is credited to the flag or the skull). A flag carrier who sprints (a fresh press) or thrusts drops it (`EXT.carryNoRun`, `game/loop.js`); the AI never does. The skull carrier may run. The rig holds either in the same two-handed grip (`skull` in `bodyState`), and the first-person view shows the flag pole or the skull.
- **Maps as data** (`data/maps.js`): each map is a versioned document (schema 1) of pieces with stable ids (`box`, `stairs`, `strip`; `twin: true` adds a 180° rotated copy for symmetric team maps), spawns, pickups, flags and lane hints. `validateMap` checks a document strictly (safe for untrusted files: types, ranges, counts, materials, ids, weapons) and `buildMap` turns it into meshes and collision; built boxes keep their piece id (`b.pid`). Navigation is built from the resulting collision boxes. A new map is a new document; a map editor or import only has to produce one.
- **Sandbox** (`game/sandbox.js`, `SANDBOX_DEFS` in `core/settings.js`): every tuning number in the Sandbox settings tab is applied to the live data (movement in `TUNE`, weapons in `WEAPON_DATA`, grenades in `NADES` / `NADE_TUNE`). The AI reads the same data, so `tools/tune.js` can measure a change by playing headless matches. Online, the room host shares its sandbox in presence and everyone else plays by it (`setSandboxOverride`) until they leave; saved settings are never touched.
- **Items on the floor** (`weapons/pickups.js`): power spawns (with rotation through `POWER_ROTATION`) and dropped items share one shape (`type`, `pos`, `avail`, `take()`). Grenades and ammo for a carried weapon are taken by walking over them (`autoTake`); other weapons need a held interact (`swapFor`). In the arena, drops travel as `drop` / `take` fx; in CTF the host owns `G.items` and clients claim them.
- **Drop pods** (`game/pods.js`): `dropPod(pos, color, { onLand })` is purely visual plus a callback; the caller places the pilot on landing and applies the crush (`podCrush` in the arena, the host in CTF). Pods fall from `POD_HEIGHT` (320 m) in `POD_TIME` (3 s), slow at first and faster all the way to a hard impact (`podLeft`: the height left is 1 − k³); the longer fall is spectacle only, so a pod launches `POD_EARLY` seconds before the respawn time and the time out (respawn delay + 1.35 s) is what it was with the old 70 m drop (all in `data/modes.js`; players, drones, CTF AI and online all use them). The spawn point is picked once when the respawn starts, passing over any spot within 2.5 m of a pilot standing there or a pod coming down or just landed (`pickSpawn`'s `taken`: `takenSpots` in the arena, `G.taken` in CTF with pods on, the client's mirror online), and steering keeps off those spots too (`podSteerClear`); one without open sky falls back to an in-place spawn at the usual time. Jump, fire or melee skips your pod camera. While you ride your own pod, move steers where it lands (`steerPod`, 9 m/s, within 14 m of the chosen spawn, only onto ground with open sky, locked for the last 18% of the fall); the mouse turns the pod camera, a ring marks the landing point, and a `podto` fx tells the room. A mode can limit it with `EXT.podZone()` (CTF: within 26 m of your own flag stand, on your half). The `spawnStyle` setting switches back to in-place spawns. On impact a pod punches into the ground up to its collar (`podSeat` picks where it rests: buried only as deep as the ground under it goes, and up to 45 cm off the landing point so it never cuts into a wall, an overhang or the air past a ledge; the pilot still appears on the point), cracks a crater (a decal kind plus kicked-up floor slabs, one instanced mesh for every pod), sends a dust shockwave out and blows its petals and cap off; the wreck smokes, then sinks away. All of it is visual: nothing is solid. Every pod in the world (and the kill cam's replayed ones) is drawn through one instanced mesh per part (hull, nose, bands, petals, cap): five draws plus the hull's shadow, however many have landed (`POD_DRAW`, written by `podDraw()` at the start of `renderFrame`). Every drop (a respawn after the kill cam, or a match start) opens from outside for 1.7 s (`podOpening`): the camera swings round your pod in your team colours as it starts its fall, settles behind it looking down at the map and pushes in through the hull with a flash into the cockpit; Jump cuts straight to the cockpit, and steering works throughout, so the time to pick a spot is unchanged. You ride your own pod from inside (`game/pod-view.js`): an HTML and SVG cockpit over the canvas (window, blast doors, readouts, brackets on the landing point, plasma, a red lamp) with the camera at the rider's eyes looking down; on impact it flashes white, the doors blow and the camera rises to your eye height. Its vibration follows Screen shake and reduced motion. The pause menu, settings, a replay (kill cam, Play of the Game) and the results screen hide the cockpit and restore the fog while they are up (`podSuspended`); leaving the match tears the drop down (`podReset`). `tools/pod-preview.js` screenshots a drop in first and third person. Power weapons come down in supply pods of their own (`game/supply-pods.js`): an armored crate with a hazard band and a blue beacon that launches from the pickup's own `availIn` (the same on the host, every client and the simulation), lands just before the weapon is due, pops its lid and holds the weapon over its rack, then sinks once the weapon is taken. Pickup timing never changes and no message was added; nothing is solid, so a pilot on the pad stands through it unharmed. The crates are drawn instanced too (four draws plus the body's shadow). Matches open with a drop too (`matchDrop` in `game/loop.js`, the Drop in at match start setting): your first spawn is a pod like a respawn (no death counted), the arena drones' as well, and a rendered CTF match starts its AI the same way (`G.start(true)`: dead, respawning at once, the time limit extended by the fall); remote players' pods arrive as the usual `pod` fx (in capture the flag on the presence fx list as `p`/`q`, so every player's pod is seen by everyone; protocol 6). The intro plays first with everyone in orbit, then all launch together, and the clock starts as they land (`FFA.t0`, CTF's clock held at its limit). Headless matches (`G.start()`) start on the ground as before; tests turn the opening drop off unless they ask for it (`open(ctx, { drops: true })`).
- **Per-frame hooks** (`game/frame-hooks.js`): features that only need the frame time register with `onFrame(fn, { menu, full })`; the loop runs them after the world and camera move and before the HUD and render.
- **AI on any map and in every mode** (`modes/ctf/map.js`, `nav.js`, `brain.js`, `agent.js`): `CTF.useMap(id)` picks the map a match is built on and derives its flags, team and free-for-all spawns, the skull's spot, pickups and lanes; the nav grid sizes itself from the map's bounds. Free-for-all makes every pilot a team of one with a brain of its own, so all the team code works unchanged: who to fight comes from `G.foes(team)` (the other team, or everyone else), never `1 - team`. Roles by mode: capture the flag plans (`chooseStrategy`) and assigns attack, defend, mid, carry, escort, chase, return and grab; Team Slayer and free-for-all hunt; oddball gives the carrier `skull` (hold out at the quietest spot near the middle), up to two `escort`s, and the rest `hunt` around the skull, everyone `chase`s an enemy carrier, and the two nearest `grab` a loose skull. Carriers close in to melee; hunters sprint and thrust in on a carrier who can't shoot back.
- **What the AI learns and how good it is** (`modes/ctf/memory.js`):
  - *Map memory:* every rendered match leaves heat where pilots died, killed and were seen, on a 3 m grid per map, saved as the `aiMaps` document (old heat fades to 80% each match, the 300 hottest cells of each kind kept, 8 maps at most). Bots read only what was known before the match, so a seed still replays exactly. They hunt toward the places fights happen, the skull carrier holds away from them, and pilots with no target watch the sight lines enemies use most (`preAim`) instead of sprinting past them. Headless matches have no memory unless given one (`tools/tune.js` `aiMemory`, `AIMEM=1`).
  - *Skill between levels:* `CTF.skillAt(level)` interpolates every number of `AI_SKILL` between Trainee (−1, easier than Recruit and never offered as a pick), Recruit (0) and Legendary (3). Offline matches use it for **adaptive bots** (`botLevel`, `botAdapt` in `game/modes.js`; Settings → Gameplay): the picked skill is the most the bots will ever be; a loss eases them off 0.4 of a level (down to Trainee), a win brings them back 0.25 toward the pick (free-for-all: by your place), saved as `botLevel` with the pick it started from. The menu's summary and the results screen show the level ("Recruit−", "Normal").
  - *The low levels against a new player:* Recruit and Normal keep their distance (`minRange`), hesitate to melee (`melee`) and gang up less on a cracked target (`focus`); Recruit was tuned against a model of a new human player (`NOVICE=1` in `tools/tune.js`) to an even fight. Against a flag or skull carrier, every level closes to 5 m and shoots, outside the carrier's one-hit swing.
  - *Habits* (`CTF.AI`, each switchable for the simulations): a hunter already in a fight lets the fight decide the range (`holdRange`; charging in made a third of free-for-all kills melee); the magnum's perfect-kill rhythm at Legendary (`rhythm`, `AI_SKILL.rhythm`): after a hit it fires again at the weapon's rate exactly, after a miss it holds fire until the aim is right on them.
- **Callout zones** (`zones` in each map document, `mapZone` / `zoneLabel` in `data/maps.js`): named boxes, first match wins, optionally owned by a team's half (`side`): the AI's comms say "our base" or "their west wing" to a team (`CTF.zoneName`), pings and the kill feed say "Red base" or "NE platform" to everyone (`zoneAt`, from the map in play, `setPlayMap`).
- **Blast gates** (`world/gates.js`, `render/gate-fx.js`, a Labs option): walls that rise out of the floor and sink on a fixed cycle. Their state is a pure function of the match clock (`gatesAt(t, on)`: the arena loop passes its match time, CTF its `G.t`, a client the host's), so every peer, replay and headless match agrees without messages. The leaves are collision boxes that move in place; a gate is a ledge you can clamber (a crouch-jump when shut) and ride up and down; `gateShove` (start of `Body.step`) moves anyone a gate rises into from below out to their side, and the AI grid patches the cells (`GATES.onNav`) from 2 s before a gate rises until it is down.
- **Spawn safety** (`world/spawns.js`, shared with the simulation worker): every spawn (pods and classic, arena and CTF, players and AI) scores the map's spawn points with `pickSpawn`: an enemy with a clear line to the spot costs a lot (more if they are looking that way), enemies within 30 m and hits or kills in the last 10 s within 18 m cost per metre, and a little jitter keeps equal spots unpredictable. Weights are in `SPAWN_W`. In the arena everyone else alive is an enemy (drones count you); CTF counts the other team. Online in the arena every client marks a fight wherever any player fires (from the fire bit in the movement everyone already sends) and wherever anyone is killed, so every client scores spawns against the same recent fights. Spawn protection (1.2 s) ends as soon as you fire, throw or melee.
- **Stats** (`game/stats.js`, `ui/stats-ui.js`): a subscriber to the event stream (kill, damage, shot, medal, flag and skull events) that keeps per-pilot numbers (time holding the skull among them) and a timeline of big moments (pod kills, flag swings and skull kills, flag denials, clutch returns, a skull held to the very end); the mode's roster (`EXT.roster`, or the arena's players) supplies who is in the match, teams and the score of record, so the same tables work offline, hosting, as a client and after a host migration (rows follow a pilot by name and team when ids change). The roster (Tab) and the results screen (`showPost`) share one sortable table.
- **HUD** (`ui/hud.js`, styles in `styles/base.css`): the default layout is grenades top left (`drawNadeHud`: icons, counts, the swap hint for `hudDevice()`, the device last used, from your bindings), shield over hull top middle (under the score bar in CTF), both weapons and the ammo counter top right (`drawWeapHud`), the motion tracker bottom left (`ui/tracker.js`: enemies only while sprinting, thrusting or hovering; teammates always). Panels redraw only when what they show changes, scale with the HUD size setting (zoom and `--hs`) and hide with `#hud` during pods, kill cams and replays. `tools/hud-preview.js` screenshots it at desktop and phone sizes. Pings (`ui/pings.js`): one mark per player (`addPing` replaces that player's last one everywhere it is shown); a double tap marks danger at the reticle point, which CTF AI teammates avoid and watch (`G.ping`, `Agent.danger`).
- **Ammo:** every weapon's reserve is finite (`data/weapons.js`, sized from simulated lives: docs/TUNING.md). Reloads take from it (yours in `game/loop.js`, the drones' `droneReload`, the CTF AI's `reloadDone`); a death drop carries what was left and online item lists send it along.
- **HUD cues:** `ui/power.js` (power spawn timer, pickup callouts and holder marks from `EXT.powerHolders`), `ui/damage-dir.js` (arcs toward whoever hit you), `sfxAt` in `core/audio.js` (stereo-panned, distance-shaped and distance-filtered sounds, a shared reverb by how enclosed the place is, footsteps by the surface underfoot), hit-marker kinds in `hitMarker`/`hitKind` (`game/state.js`).
- **Map dressing** (`world/dress.js`): runs inside `buildMap` before merging and never adds collision. The worker build skips it (it has no `dressMap`). `world/props.js` adds pipes, cables, wall fans (spun in the vertex shader), beacons and holographic signs, merged per material and hidden by the Map detail setting.
- **Graphics** (every effect sits behind a graphics setting, and the presets set them all; Low keeps only what is baked):
  - *Baked light* (`world/bake.js`): `buildMap` rebuilds static boxes as world-space gridded faces and bakes ambient occlusion and strip-light bounce into a `bake` vertex attribute; `MAP_GROUPS` remembers each built map's id for the per-map grade and floor markings.
  - *Surfaces* (`render/surfaces.js`): one `onBeforeCompile` patch for the map's standard materials: baked light, procedural world-space panels with edge wear and grime, floor markings painted from the map document, wet patches. The dev console's `bake` command shows the baked light alone.
  - *Post* (`render/pipeline.js`): half-resolution SSAO, screen-space reflections on the floor at High and Ultra (surfaces leave their reflectivity in the scene target's alpha: wet patches fully, polished plates and deck tops partly; sky is alpha 0, which the light shafts use as their mask), light shafts toward the sun, a per-map grade (`MAP_GRADE`) and heat haze, all in or before the one composite pass. The perf overlay (F3) shows GPU time per pass.
  - *Combat effects* (`render/combat-fx.js`): pooled point lights, instanced casings, debris and decals; `tracer()` and `blast()` call into it, so every shooter and explosion gets them (and every shooter but you a muzzle flash where the shot leaves the gun). A bullet's tracer is a short streak flying at `TRACER_V` (`render/fx.js`); the sniper's trail and the beam stay drawn lines.
  - *Melee impacts* (`meleeFx` in `render/combat-fx.js`): whoever decides a blow (you, or the AI where it runs) plays it at the contact point and sends it as an `mhit` fx (arena presence, CTF host and client fx lists), so everyone nearby hears it positionally. A pilot hit thuds (`mhit`, `mkill` from behind, `mcrack` layered when the shield breaks); a swing that meets the world within reach (`meleeWorldHit`) clanks (`mwall`) with sparks and grit; the charge has its own pair (`chit`, `cwall` on the physics `bump`).
  - *Sprint thrusters*: `rig.update` sets `rig.jet` (0..1 with speed) and flickers the pack's glow sprites; `sprintJets` (from `rigEvents`) adds exhaust sparks within 60 m (Combat effects), a breath of heat haze (Ultra) and a pulsed whoosh. In first person you only hear it (`myFeel`).
  - *Characters* (`characters/look.js`): `makePilot` ends with `styleRig(rig)`, which only patches materials (rim light, panel lines, team pattern, the visor following the shield, the shield's hex ripple), so the rig's animation code stays separate.
  - `tools/gfx-preview.js` screenshots fixed views at any preset (`--hw` for the real GPU and its per-pass timings, `--fx`, `--pilot`).
- **Draw-call budget:** static map pieces are merged into one mesh per material when a map is built (`mergeMapGroup`; destructible cover keeps its own meshes), and each pilot's parts are merged per bone and material with one shield shell per bone (`mergeParts`, geometry shared by all pilots). Bloom runs at quarter resolution and tone mapping happens once, in the composite pass. The CTF budget is measured in play right after the opening drop (every wreck on the map, world frozen, every team spawn at eight headings). Worst-case views went from ~466 to ~305 draw calls in the arena and ~955 to ~545 in CTF; `tests/budgets.json` holds the limits.
- **Multiplayer topology** (`net/p2p-transport.js`): the room host relays presence (reliable: names, scores, hits, events, flags); every pair of players also has a direct unordered, no-retransmit link for movement (full mesh, hub relay as fallback). Rooms expose `fast(buffer, to?)`/`onFast(fn)` on top of the presence API, so a transport without them (a relay server, a platform room service) still works on presence alone. The host names a backup; if the host leaves, everyone moves to the backup and the room carries on (`migrate`), and the backup claims the room code. The host can hand the room to a suggested better host. A CTF match survives its host leaving: the successor (room backup if in the match, else the lowest peer id) rebuilds a real match from its mirror (time, score, flags, agents) and hosts it under the same match id (`promote` in `modes/ctf/modes.js`). Presence goes out as deltas: after a full first send, only changed top-level fields (and the changed fields of a plain object such as the CTF host's snapshot) travel; joiners and a new host get everything in full. Movement is on the fast channel, so presence repeats it only once a second as a fallback, and the CTF host refreshes each agent's movement fields in its snapshot once a second. A CTF host sends at once (at most every 33 ms) when there are kills, flag events or hits to deliver. If two players take over the same match at once, the one with the lower peer id keeps it and the other joins them.
- **Remote playback** (`net/playback.js`): movement packets are timestamped with the sender's clock; each remote player has a buffer with an estimated clock offset and an adaptive delay (about one send interval plus jitter), sampled every frame with interpolation and brief extrapolation. Arena movement goes out at 40 Hz, CTF movement at 30 Hz.
- **Lag compensation and hit checks** (`net/hitcheck.js`): a hit claim carries the shot's ray, the shooter's clock when they fired and the victim's clock time the shooter was seeing them at. Everyone keeps a short history of each player's reported movement in that player's own clock (`MoveHist`; your own in `MY_HIST`), so a claim is checked against where the victim really was on the shooter's screen. The rewind is capped (`HITCHK.T.CAP`, 0.5 s from the victim's view time to the shot landing): a shot reaching back further is checked against where the victim was 0.5 s before it landed. In the arena the victim decides hits on themself with this check and publishes refusals (`hr` in presence) so the shooter knows; the room host runs the same checks on every claim it relays. In CTF the host checks every client claim against the recording (`REC`) the same way. Rejected: the ray misses the rewound body (0.8 m from its axis), a wall cuts it, out of range, fired from somewhere else (1.6 m), faster than the weapon fires. Flagged only (they depend on every movement packet arriving): aim against the reported view (0.4 rad), shots past a magazine without a reload, swap or death. The host logs verdicts per shooter, re-checks failed ones against the recording once it holds the moments around them (and at match end), and shows the summary in the network panel (F4) and on its results screen. `tests/net.test.js` measures it under ideal, bad, lossy and awful links (`tests/lib/fairness.js`).
- **Background simulation** (`src/worker/`, built to `sim-worker.js` next to `index.html`): the simulation modules (physics, destruction, grenades, map, the CTF AI and rules) with rendering stubbed out by `three-lite.js`. AI training runs there, so it never stalls rendering; pages opened from a file fall back to slices on the main thread. The headless tests load the exact same bundle (`tools/sim-bundle.cjs`). Live matches still simulate on the main thread. Measured in a rendered 4v4 capture the flag match (desktop CPU): `G.step` takes 0.36 ms per frame on average, 0.8 ms at the 95th percentile, 2.3 ms at worst, of a 16.7 ms frame (headless, 0.1 to 0.16 ms per 30 Hz step). Moving it would not make the main thread measurably cheaper: a rendered step does its presentation inline (tracers, sounds, pods, events, the host's snapshots and hit checks against you), all of which would come back as messages, and the AI would see you and hit you a frame late, so play would no longer be identical. The worker bundle is the path if matches grow (16 players, more AI).
- **Network messages** (`net/messages.js`): every message is defined once (id, reliable or fast channel, typed fields such as `v3:100` fixed-point vectors, wrapped angles and capped strings). `MSG.encode`/`MSG.decode` are generated from the definitions; decode returns `null` for anything truncated, padded, unknown or out of range and never throws (fuzzed in `tests/messages.test.js`). `MSG.PROTOCOL` is checked by the transport when a friend joins: a mismatch shows both players a clear "different versions" message. Bump it whenever a message changes shape.
- **Save data** (`core/store.js`): everything saved is a named, versioned document (`pilot`, `settings`, `ctfTeam`, `ctfBrain`) in an envelope `{app, doc, version, savedAt, data}`. `STORE.load` runs migrations then the document's `clean()`, ignores junk and leaves saves from a newer build untouched; `STORE.save` keeps the previous copy as `<key>.bak` (`STORE.restoreBackup`). The backend (`get/set/remove/keys`) is swappable, so career stats, map files and a chosen save folder can be added as more documents and another backend.
- **Network diagnostics:** each connection is a `Link` that measures round trip, jitter, loss and bandwidth. `?netsim=latency,jitter,loss%` (or `KAHOST.net.setSim`) adds simulated lag and loss to everything a tab sends; F4 shows the panel and F3 the performance overlay. `tests/net.test.js` records how far behind and how far off a remote player is drawn under ideal and bad links.
- **Network lab** (`tools/net-lab.js`, `tests/lib/netlab.js`, [NETLAB.md](NETLAB.md)): separate game instances, each its own browser process, form a room and play real matches in every mode with automated players (`tests/stubs/lab-bot.js`), over a local relay that simulates each link (delay, jitter, bursty loss, reordering, spikes, bandwidth) or over real WebRTC with a local signalling server. It reports position error and delay, correction pops, bandwidth by message type (`KAHOST.net.traffic`), hit registration and false rejections, kill-to-display time, desyncs, host migration time, and time in net code (`KAHOST.prof`, parts timed with `netProf`/`timed`) and garbage. `tests/netlab.test.js` runs it at CI size.

## Developer console

In a dev build (`npm run dev`) or with `#dev` in the page address, backquote opens a console: `tp`, `give`, `god`, `timescale`, `bots`, `hitboxes` (the exact boxes shots are tested against), `nav` (the CTF AI's walkable grid), `net` (simulated latency, jitter and loss), `seed`, `events`, `pilots`, `perf`, `netpanel`, `kill`. Commands live in one table in `src/ui/console.js`; add new ones there.

## Scenario tests

`tests/lib/scenario.js` runs scripted situations against the real movement, collision, hit and rules code in Node, in milliseconds: place pilots, give them inputs per tick, then assert on positions, events and hits. `tests/scenarios.test.js` holds the current movement "feel contract" (walk, sprint, strafe, thrust, jump, slide, pound), hit registration (head and body boxes, crouching, walls) and CTF rules (pickup, capture, drop, reset). Sandbox tuning should change those numbers deliberately, in the same commit.

## Visual regression

`tests/visual.test.js` renders the menu, an arena view, a pilot close-up and a trailer frame (from the trailer build) with real three.js in software WebGL (the world frozen with `timescale 0`) and compares each with the approved screenshot in `tests/visual/` on a 160x90 downscale (mean difference ≤ 6/255, ≤ 3% of pixels changed a lot). When a look changes on purpose, approve it with `VISUAL_UPDATE=1 THREE_PATH=... node tests/visual.test.js` and commit the new PNGs; a failing run writes `<name>.actual.png` next to the approved one.

## Code quality

- **Formatting:** Prettier (`npm run format`), checked in CI.
- **Linting:** ESLint with a generated shared-scope config: each engine module is linted with the names declared by the other engine modules as globals, so a misspelled or missing name anywhere fails the build (an engine module written as an ES module gets only what it imports). `tools/check-unused.mjs` reports engine declarations nothing uses.
- **Types:** TypeScript checks every source file as JavaScript (`npm run typecheck`, no rewrite). The engine API's type is inferred from the object in `src/game/exports.js`, so mode modules are checked against the real API. Wire formats and the settings schema are declared in `types/`.

## Building and testing

node build.mjs --check    # fails if they are out of date (CI runs this)
node tests/sim.test.js    # two headless AI matches
node tests/browser.test.js
THREE_PATH=path/to/three.module.min.js node tests/render.test.js

The trailer is not part of the game. `src/manifest.json`'s `trailer` section lists its modules (`modes/trailer-score.js`, `modes/trailer.js`), markup (`html/trailer.html`) and styles; `node build.mjs --trailer` writes `out/trailer.html`, the game plus those files, and the recorder, the previewer and the trailer tests open that page (`open(ctx, { trailer: true })` in `tests/lib/browser.js` builds it). The game's Watch trailer button plays the recorded `media/trailer.mp4`.

The trailer (`modes/trailer.js`) is a pure function of trailer time: live it is clocked by the music's audio context; for video capture it is stepped frame by frame (`KA.trailer.record()`, `KA.trailer.step(dt)`), and the score (`modes/trailer-score.js`) renders to a file through an `OfflineAudioContext`.

Each trailer shot is `{ t, setup, update(lt, dt, st), ts, look, mood }`: `ts(lt)` ramps time (slow motion), `look(lt)` sets depth of field and grade (`af(point)` focuses on a point), and `mood` sets the sun, sky and fog. Actors are `Pilot`s whose `ctl(actor, simTime)` returns input every 120 Hz physics step; `steer()` follows a route of points by turning toward a spot a little ahead on it, like a person running, so motion doesn't depend on frame rate. The physics emits a `bump` event when a body hits something solid at speed; the trailer logs those in `KA.trailer.diag.bumps`, logs any frame where the camera is inside geometry in `diag.cam`, and the browser test simulates the whole cut and fails on either. A shot with `fp: true` is first person: `KA.trailerFP` (`game/trailer-fp.js`, a trailer-only engine module) places the player and steps the real `frameBody` with scripted held and pressed actions and where to look, so the HUD, viewmodel, firing, clamber and pod cockpit are the game's own; the trailer's mode hooks supply what the player can shoot (`targets`), the tracker's contacts (`radar`) and a carried flag or skull (`carrying`). While recording, the full-screen frame hooks (effects, atmosphere, supply pods) run on trailer time instead of the page clock, so captures repeat exactly. `tools/trailer-preview.js` runs the same check, renders contact sheets of stills, or short clips with the score.

The browser tests use stubs in `tests/stubs/`: a minimal three.js stand-in and an in-memory PeerJS replacement, so two or three tabs can play online against each other without a network. The build refuses to emit a module containing a closing script tag or an unresolved template directive.
